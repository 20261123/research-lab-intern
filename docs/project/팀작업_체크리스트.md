갱신일: 2026-10-10 · 기준 코드: labgemini4.m · 담당은 역할별 배정안

본인이 진행해 공유한 코드·보고서·실행 결과와 GitHub 보관 내역을 기준으로 갱신했다. **세 조건의 첫 비교와 보고서 수정까지 완료했으며, 좌표 근거 확인과 세종대 추가 배치 실험이 남아 있다.** 일차는 실제 달력 날짜가 아닌 작업 단계다.

`[x]`는 자료 또는 실행 기록으로 확인한 완료 항목이다. `[ ]`의 “부분 완료”는 아직 완료 조건을 충족하지 않은 상태다. 파일 작성, 실행, 팀원 이해, 리허설, 제출을 서로 구분한다.

## 앞으로 파일을 받을 때의 갱신 원칙

1. 새 파일의 내용과 버전을 먼저 확인한다.
2. 완료 근거가 있는 항목만 체크하고 근거 파일을 연결한다. 미실행 코드나 주장만 있으면 부분 완료로 둔다.
3. 코드·좌표·조건이 바뀌면 이전 결과·보고서의 유효성을 확인하고 필요한 항목을 재검토로 돌린다.
4. 예제와 세종대, 파일 작성과 실행·해석·리허설을 구분한다.
5. [진행 기록](진행기록.md)과 [조원별 다음 할 일](조원별_다음할일.md)을 함께 갱신하고 GitHub에 반영한다.
6. 필요한 MATLAB 실행 결과를 확인할 수 없으면 본인에게 요청하고 숫자를 임의로 만들지 않는다.
