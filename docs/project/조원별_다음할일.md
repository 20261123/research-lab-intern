## 최신 확률·장애 검증에 따른 후속 업무

A는 팀 PC 재현과 확정 채널/부하 모델 검토, B는 추가 11번 (-17.5,22.5) m의 실제 전원·전송 경로·대체 커버리지 확인, C는 장애별 실내 QoS와 복구 순위 검토, D는 결정론/확률 결과를 구분해 PPT에 반영한다. 11번을 먼저 복구하는 효과가 가장 크며, 대체 대역 선택은 지연·부하 재분배를 제외한 이상적 가정이다. 현장 조치·실제 복구 시간·장애 최적 배치 완료로 처리하지 않는다.

## A 코드 담당

1. 조원 PC에서 labgemini4를 실행해 기존 통계와 일치하는지 확인한다.
2. 중복 좌표·미계산 표본·NaN·Inf를 검사하고 조건표를 남긴다.
3. 다른 조건은 고정하고 부하율 0.5와 1.0을 비교한다.
4. B의 후보 8곳 중 2곳을 추가하는 28조합 비교 기능을 연결한다. 기존 사이트는 유지한다.
5. 같은 위치·전력·안테나·모델로 추가 전후를 계산한다. 확률 요소를 쓰면 기존 링크 난수를 유지한다.

**받아야 할 결과물:** 코드, 실행 방법, 조건표, 검증 기록, 28조합 결과표. 코드만 받고 완료 처리하지 않는다.

## B 지도 담당

새 참고자료: [캠퍼스 둘레·7개 건물 개념도](../../results/maps/sejong_7regions/). 사진 경계의 개념 표현은 작성 완료했으며, 원점·축척·회전과 건물 위치를 확인한 뒤 실제 경계 좌표를 A에게 전달한다. A는 경계 내부 사용자 마스크를 적용하고 C와 세 조건을 다시 계산한다. 현재 MATLAB 결과는 기존 사각 격자 기준이다.

1. 현재 서비스 9개·외부 6개 사이트·7개 건물의 출처와 조사 날짜를 확인한다.
2. 지도 원점·x/y 방향·m 환산·사업자 확인 상태를 적는다. 미확인 값을 확정 사실로 쓰지 않는다.
3. 실지도와 평가 영역 x −150~150 m, y 0~550 m 및 건물 사각형을 대조한다.
4. C의 취약 지도를 받아 후보 8곳을 고르고 좌표·높이·설치 가정·제약·선정 이유를 적는다.

**받아야 할 결과물:** 기존·외부 사이트 좌표표, 건물표, 조사 근거, 후보 지도와 후보표. 후보표 필드는 ID·x·y·높이·선정 이유·설치 가정·제약이다.

## C 검증과 분석 담당

1. 현재 결과에서 실내·실외 각각의 평균·중앙값·5백분위를 집계한다.
2. 28 GHz 취약 위치를 지도에 표시하고 거리·실내 손실·간섭으로 원인을 구분한다.
3. 28조합을 28 GHz/800 MHz 전체 5백분위, 동률이면 중앙값·평균 순으로 비교한다.
4. 선정 배치의 두 대역 추가 전후를 비교하고 개선·악화 구간을 모두 표시한다.
5. 그래프마다 관찰한 사실과 원인을 한 문장씩 적는다.

**받아야 할 결과물:** 실내·실외 통계표, 취약 지도, 후보 순위표, 추가 전후 Heatmap·CDF, 개선율·악화율 표. 5백분위와 하위 5% 평균을 혼용하지 않는다.

## D 조장과 발표 담당

1. 지금 있는 보고서의 오류·수정·비교 결과·한계를 발표용으로 정리한다.
2. 예제 PPT는 구성만 참고하고 지도·수치·그림은 현재 세종대 결과로 교체한다.
3. 배치 실험이 끝나면 후보 비교표와 추가 전후 결과를 넣는다. 없는 개선 수치를 먼저 쓰지 않는다.
4. 문제 → 지도·조건 → 수정 → 주파수·대역폭 비교 → 위치 선정 → 추가 전후 → 한계 순서로 구성한다.
5. 팀 리허설과 질의응답을 진행하고 발표 시간을 확인한다.

**받아야 할 결과물:** 최종 PPT, 발표 분담과 대본, 질의응답 목록. 왜 28 GHz인가, 왜 이 두 위치인가, 악화된 곳은 없는가, 실제 속도인가에 답할 수 있어야 한다.
